Branch

Branch Nedir?

Branch, bir repodaki porjenin farklı varyasyonlarını depolayabilceğimiz ve yönetebilceğimiz repo kısımlarına denir.
Branch Türkçe anlamıyla dal bizim için bir nevi projenin farklı varyasyonlarını farklı repo açmadan aynı repo içerisinde depolayabilceğimiz ve yöneteceğimiz kısımlardır. Örnek olarak bu dökümantasyonun mobil uygulama versiyonu projesini bu dökümantasyonun farklı bir Branch'a koyulabilir veya bir uygulamanın farklı mimariler için farklı Branch'lar kullanmasıda Branch kullanıma örnektir. Görsellik bakımında aşağıdaki örneğe göz atalım

HEAD

HEAD, mevcut Branch'ı ifade eden ve ".git" klasöründe bulunna bir dosyadır. Hem bize hemde Git'e hangi Branch'a olduğumuzu söyler.
cat .git/HEAD
        
Komutu ile neler yazdığını görebiliriz.

Çıktı;

Master → Main

Daha önceden bahsettiğimiz gibi eskiden ana Branch dolayısıyla tüm ana kodlar "master" adlı bir Branch üzerinden yapılırdı. Fakat zamanla alışkanlıklar değişti daha kapsayıcı olan "main" ismine geçildi. Çünkü 2020 yılındaki genel olarak farkındalık kazanan insanlar Git ve Github sisteminde rahatsız edici buldukları için... Branch sistemi yurt dışında o zamanlarda "Master Slave ilişkisi" üzerinden anlatılırdı. Master-Slave Türkçesiyle sahip-köle, bu iki kavram insanları rahat edici gelmeye başlamıştı. Bu durumda Git ve Github Master'dan Main'e geçiş yaptılar. Böylelikle üzerlerindeki kültürel baskı ortadan kalkmış oldu...

Git Branch

Bu komut Branch işlemlerini gerçekleştirmek için kullanılan Git komutudur.

Listeleme

Branch'ları listemek için;

git branch

Komutu kullanılır.

Tüm Branch'ları görüntülemek için ise;

git branch -a

Komutu kullanılır.

Oluşturma

Branch oluşturmak için;

git branch branchIsminiz
            
Şeklinde oluşturulur.

Kontrol etmek için listeleme yapalım;

git branch -a

Branch'ı Yeniden Adlandırma

Yeniden adlandırmak için;

git branch -m eskiBranchIsmi yeniBranchIsmi

Branch Silme

Branch silmek istersekde;

git branch -d branchIsminiz


Zorla silmek istersek;
git branch -D branchIsminiz

Şeklinde kullanılır.

Git Switch

Git Switch, Branch'lar arasında geçiş yapmamızı sağlayan bir komuttur.

Branch'a Geçiş

Branch arası geçiş yapmak için;

git switch branchIsminiz

Oluşturup Geçme

Eğer Branch yoksa ve direkt oluşturup geçmek istersek;

git switch -c branchIsminiz

Branch Stratejileri

Branch'ı kullanmak esasen bir strateji üzerine kurulur. Projemizin ekibimizin büyüklüğü ile direkt ilgili olan bu stratejileri bir gözlemleyelim.

GitHub Flow

En basit ve küçük ekipler için uygun olan strateji olan Github Flow, iki adet Branch gerektirir. Main ve Feature Branch'larını ister
Main Branch'ın amacı projenin ana kaynak kodlarının barındırmasıdır.
Feature Branch'ı ise yeni özelliklerin, düzeltmelerin ve denemelerin yapıldığı bir nevi deneme tahtası işlevi gören kısımdır. Feature'daki proje yayımlanmaya uygun olduğunda Main'e ya Merge ya da dosyaların üzerlerine yazma işlemi ile Main'e yazılır ve ana proje olmaya başlar.

Git Flow

Bu strateji ise kapsamlı projeler ve büyük ekipler için uygundur. Kullanılan Branch'ları ve işlevlerini görelim;
Main, genel sürüm yükseltmelerde güncellenen Branch'tır.
Develop, bu Branch'ta tüm geliştirme süreci gerçekleşir. Tüm özellikler ve düzeltmeler işlemlerin sonucunda Develop Branch'ı ile birleştirilir.
Feature, Develop Branch'ı için özellik denemeleri bu Branch'ta gerçekleşir.
Release, genel ve ara yükseltmelerde güncellenen yegana tüm sürümlerin bulunduğu Branch'tır. Main'den farkı ise; Main'e giden veriler "0v, 1v, 2v" gibi sürüm numaraları giderken, Release ise "0.1v, 1.1.4v" gibi sürümler gider. Yani Main genel olarak Feature her yükseltmede güncelleme alır.
Hotfix, Develop Branch'ındaki acil hata düzeltmeleri için bu Branch kullanılır.

Trunk Based Development(Ana Hat Tabanlı Geliştirme)

Bu kısımda stratejide ise özel amacı olan herhangi bir Branch açılmaz. "Main ve açılan Branch'lar ne olursa olur her zaman yayımlanmaya müsait olduğu sürece repo her zaman iyidir" şeklinde strateji ile yola çıkılır.
